# friction.md — cupo idrd build (2026-11-03)

Appended as it happened. Feeds the case file and corrections to `cli-build` / `cligentic`.

- **Phase 0 classification: discovered.** Recon report existed before the build; started from it, not from the portal.
- **Recon over-reported availability.** The first manual scan counted `can:true` windows as free. Live data shows "Espacio Reservado" windows stacked on top of "Espacio Reservable" ones; 11537 Wed 06–08 looked free and was fully booked. Fixed in `availability.ts` with a test built from the live fixture. Lesson for `surface-recon`: when a calendar endpoint returns overlapping categories, the free set is a difference, not a filter — verify by contrast against the portal UI before reporting slots to a human.
- **Schedule endpoint ignores the date for the week.** `?date=2026-11-12` returns the current week (11-03..11-09). Booking is only possible inside the published week; enforced as a rule and surfaced in `slot list` (`outsidePublishedWeek`).
- **Portal rules live in prose.** Max 2 h/day, 4 h/week, 24 h advance are only in the `requirements` markdown of each court. Encoded in `rules.ts` as pre-checks; the server stays authoritative.
- **cligentic `prompt-secret` writes its label to stdout.** With stdin a TTY and stdout piped (`cupo cupo idrd auth login | jq`), the label corrupts the JSON. Patched to stderr (hybrid). Worth an upstream fix.
- **cligentic `argv` swallows the next positional after a boolean flag** (`--json 11537` → `json="11537"`). Wrapped with a boolean pre-pass. Worth an upstream option (`booleans: [...]`).
- **cligentic `json-mode` vs the skill's envelope.** `emit()` writes arrays as NDJSON and puts next steps on stderr; `cli-build` asks for `nextSteps` inside the structured output. Chose the envelope; the two references disagree and should be reconciled.
- **cligentic `global-flags` uses generic env names** (`CLI_JSON`, `CLI_PROFILE`), which collide across CLIs on the same machine. Renamed per CLI.
- **cligentic `killswitch.assertKillswitchOff` throws a plain `Error`** — no code, no hint, no exit mapping. Used the state getter instead.
- **Double-encoded UTF-8 from the portal** (`NÂ° 1`, and cp1252 variants like `PEÃ‘ALOSA`). `cleanText` repairs only when the re-decode is valid UTF-8.
- **No cancel endpoint anywhere.** Changed the trust design from T2 to T3 for `booking create`.
- **The SPA sends a hardcoded IP to PSE when its IP lookup fails.** Rejected that behavior: the CLI uses the real public IP or stops.
- **Test harness deadlock.** `spawnSync` in a bun test blocks the event loop, so an in-process `Bun.serve` mock never answers → 90 s timeouts. Switched to `Bun.spawn`. macOS `script` (to get a real TTY) waits on stdin unless it is `/dev/null`, and echoes `^D\b\b` at the start of output.
- **zsh glob ate `--include=*.ts`** in the Phase 5 grep, producing "0 call sites" for everything — a false wiring alarm. Quote the pattern. The skill's "grep for the call site" check should mention this.
- **Human output review caught what tests could not:** per-hour lists truncated ("4:00 PM, 5:00 PM, …") → compact ranges ("4–10 PM"); a rule summary that matched "máximo" inside a damages paragraph; an English "Next steps:" header in an otherwise Spanish CLI.
- **Phase 4 not exercised live by design.** No credentials during the autonomous build and the owner chose not to create a booking (irreversible). Contract tests cover the gates; first real booking is the remaining verification.
- **Self-review: a created booking could vanish from the output** when the follow-up payment step failed. Irreversible writes need their id reported even on partial failure. Fixed + test. This belongs in `cli-build` Phase 4 as a rule: after an irreversible write succeeds, nothing downstream may turn the result into an error that hides it.
- **Pre-publish scan found the portal's web-client secret hardcoded** in `api.ts`. Not a user credential (every browser gets it), but a public repo should not republish it and a literal breaks on rotation. Replaced with discovery from `chunk-common.<hash>.js` + 7-day cache + re-discovery on `invalid_client` + env override. A pre-publish secret/PII grep belongs in `cli-build` Phase 6 before "ship".
- **First public install failed on paste.** The README install block had trailing `# comments` with parentheses; interactive zsh does not treat `#` as a comment by default (`interactivecomments` off), so the pasted block died with `parse error near ')'` and nothing ran. Copy-paste blocks must contain only commands; explanations go outside the fence. Worth a line in `cli-build` Phase 6 (the README is part of what ships).
- **The README contradicted itself** ("no necesita Bun" next to `bun install && bun run build`). Fixed by committing the Node bundle so install is `git clone && npm link`.
- **Court lists are paginated and the CLI read only page 1.** Every `/api/parks/*-courts|*-fields` response is a Laravel paginator (`meta.per_page: 10`, `meta.last_page`, `links.next`); the recon fixture `recon/idrd/tennis.json` even shows `total: 88`, but recon and build both read `data` and ignored `meta`. The CLI showed 50 of 320 courts (tennis 10/88, sintética 10/180) and a locality filter for Chapinero came back empty although the portal has a court there. Fixed in `api.ts`: ask `per_page=500` (honoured live, Nov 2026) and still follow `meta.last_page`, with a hard stop and a coded error if the server ever caps pages past 50. Two contract tests: a mock that caps pages at 10 rows (must fetch 4 pages for 37 courts) and one that honours `per_page` (must make 1 call). Lesson for `surface-recon` and `cli-build`: when a list response carries `meta`/`links`, the contract is the paginator, not the first page; the suspicious signal was five sports returning exactly 10 rows each.
- **"100% of courts" was 15% of the portal.** The endpoint table in `chunk-common` lists every service in one place (`SWIMMING_POOLS`, `GRILLS`, `GYMS`, `COLISEUM`, `CITIZEN_PORTAL`, `GYM_MEMBERSHIP_*`, `PORTAL_PROFILES_*`, `PORTAL_PENDING_TO_PAY`). Recon only followed the five it was asked about. Lesson for `surface-recon`: enumerate the whole endpoint table and classify it before scoping, so "coverage" is stated against the portal, not against the request.
- **Pools return an empty calendar without `lane`.** Not an error, just `data: []`. The SPA selects the first lane silently. The CLI refuses without `--lane` and lists the lanes in the hint; `find --sport pool` expands every pool into its lanes (37 calendars in ~3 s with concurrency 8).
- **Capacity spaces reuse the same calendar with `quota`/`used_quota`**, and the server replaces a full hour's reservable window with a `can:false` "Espacio No Disponible" that still carries the numbers. The difference algorithm needed one addition: taken windows with a quota are shown as "sin cupo" rather than dropped.
- **The kind of space is only knowable from the calendar response** (`details.details.endowment`), the same way the SPA decides which form to render. `booking create` probes the calendar first, then decides lane/sport/block semantics.
- **`--profile` collides with the global account flag.** Activity enrolment uses `--person <profileId>`. Found by a test that silently got `auth/required` because the account profile became "900".
- **Multi-hour published blocks (coliseums 12–2 PM, grills 8 AM–4 PM) break the 1-hour slot model.** Added `blocks()` beside `hourSlots()`; grills book the whole block by default; other non-court kinds must fit inside one block (the 2 h prose rule is courts-only).
- **Membership payment = booking payment minus `reservationId` plus `membership_id`.** The SPA builds both from the same form; it also stores `last_payment_code` in localStorage to activate on return. The CLI exposes activation as `gym activate --code`, the human's responsibility after paying.
- **Activities filter server-side only by `program_id[]` and `stage_id[]`** (array syntax; the scalar form returns nothing). `query=` is accepted and ignored. Text, age, price and places are filtered client-side after reading every page (74 rows today).
- **2026-11-04 — Second target, same CLI.** The CEFE Chapinero the owner kept asking about is not an IDRD facility: it runs its own Next.js + API Gateway platform at cefechapinero.com. Phase 0: **discovered**; recon in `docs/recon-cefe.md` (bundle read, 7 anonymous endpoints replayed). Added as the `cefe` namespace of the same binary rather than a second CLI: one install, one agent manual, shared blocks; separate session store (`~/.cupo/cefe/`) and `CEFE_*` env names because the accounts are different.
- **`new URL(path, base)` drops the API Gateway stage.** With base `…/main` and path `/pools`, the URL resolves to `/pools` at the host root; API Gateway answers 403 "Forbidden" for any unknown route, which reads exactly like a WAF or an auth failure. Every CEFE call failed with `auth/forbidden` until the join was made string-based. Lesson for `cli-build`: when a base URL carries a path, test one anonymous GET through the real `request()` before wiring commands; the recon's curl calls had hidden the bug.
- **The classifier blocked a header-by-header 403 bisection** (User-Agent variants) as bot-check circumvention. It was the wrong experiment anyway: the failure was the path join, not a header. Order of suspicion for a 403 from API Gateway: route, then auth, then headers.
- **Two of the SPA's rules are calendar switches, not server rules**: free practice is free until 2026-11-04 and 10,000 COP per person from 2026-11-05; classes, enrolments and promotion purchases are "disabled from 2026-07-30" in the web only. The CLI mirrors both as checks and labels them as the web's rules, because the backend's view is unverified.
- **Wompi keys ship in the bundle.** The checkout widget needs a public key and an integrity value that the SPA hardcodes. Not reproduced in this repo and not used: WOMPI bookings and enrolments are created `pending` and the human finishes payment on the website. Same decision as the IDRD web-client secret, for the same reason.

- **Rename by regex is safe only with a green suite behind it.** Prefixing 143 command strings and 141 test argv arrays by script introduced two wrong prefixes (an `id` argument renamed `idrd id`; envelope command names double-prefixed to `cupo idrd …`). Both surfaced in the first test run. A rename without that net would have shipped `--help` text that lies.
- **`find` across providers needs a normalized unit.** IDRD speaks hours on the hour (plus a lane); CEFE speaks published 60-minute slots at odd minutes (07:15). The common shape is `free[]{start, end, places?}` in HH:MM plus the provider's own `bookCommand`; the CLI never tries to merge the two booking models, it only lines them up.
